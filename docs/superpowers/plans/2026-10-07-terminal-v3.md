# Terminal v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ranked clips with a score, reuse of one clip for up to three characters, and a studio-at-a-glance home, with the hit rules in every cloud check.

**Architecture:** The free check (`studio/drop.py` + `studio/gemini.py`) adds a score and reads `config/hit_rules.md`; a version of a drop is a new pick sharing the root's source (`drop.copy_of`), filed by `studio drop copy` or the RPC `studio.copy_drop`; scheduling keeps a family's posts 14 days apart in Python and SQL alike; the terminal reads `drop_card.score` / `copy_of` and a new `v_views_daily`.

**Tech Stack:** Python 3.12 (uv, typer, psycopg 3, pydantic 2), Postgres (Supabase, schema `studio`), Vite + React + TypeScript (Vitest).

**Spec:** `docs/superpowers/specs/2026-10-07-terminal-v3-design.md` (read it: every section number below refers to it).

## Global Constraints
- All state goes through `bin/studio` / the studio Python package or the migration's RPCs; schema `studio` only; additive migration `supabase/migrations/0015_terminal_v3.sql` (never applied by a task: the controller applies it).
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; commit email = the GitHub no-reply; no media in git.
- Never generate (no Higgsfield call, no `request_job(..., 'make')` from code paths other than the owner's button); no secrets in files; never edit `.claude/settings.json`.
- Plain-English UI copy (spec §1); phone first (375 px), no sideways page scroll.
- `uv run pytest -q` and, for terminal tasks, `cd terminal && npm test && npm run build` green before each commit.
- MAX_FAMILY = 3; FAMILY_GAP_DAYS = 14 (no family member's post within 13 days of another's); score total = round(10 × (0.6 × potential + 0.4 × swap)).

## Review Focus
1. A version of a version must point at the ROOT (`copy_of` = root id), and the family count must ignore skipped picks: otherwise a 4th member slips through.
2. The family spacing must be identical in Python `free_slot` and SQL `studio.free_slot` (parity cases), including posts of members on OTHER accounts of the same character and the clip being scheduled itself excluded.
3. A drop checked before this build has no `score`: every terminal ranking must handle it (after the scored ones, newest first) without NaN or a crash.
4. Recheck must refuse a drop with the owner's Make it (`make_requested`), `making` or `made`: re-checking would move a paid job.
5. The tick-and-make bar must never fire without the confirm, and must report each pick's own result (one failure does not hide the others).
